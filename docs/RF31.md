# RF31 — Gráfica mensual

Issue #40. Rama independiente desde main c64a25c. Panel P12 sustituye su marcador por una gráfica de seis o doce meses, sin bibliotecas adicionales. Scroll y texto equivalente permiten leerla con letra grande o lector de pantalla. Conserva cierre de sesión.

`GraficaIncidencias` → `useReporteMensual` → `repositorios/reporteMensual` → vista `reporte_incidencias_mensual`. La vista existente agrupa por date_trunc('month', creada_en at time zone 'America/Lima')::date y usa security_invoker: hereda RLS de incidencias. La app no descarga ni agrupa reportes individuales. La ruta y el hook habilitan el reporte para directiva; consultar la vista con otra cuenta no amplía sus permisos de lectura.

El rango incluye el mes actual de Lima y cinco/once anteriores, en orden. Un mes sin fila muestra cero. No se interpreta la medianoche SQL como UTC para evitar mover el rótulo al mes anterior. Las cantidades se validan como enteros no negativos y el total debe coincidir con los estados. Pendientes/en atención/resueltas son estados actuales de reportes creados en ese mes; no es una serie histórica de transiciones.

La consulta se separa por cuenta y rango. Recupera al volver al Panel o a primer plano; un temporizador local revisa el cambio de mes, sin polling de datos. Hay estados de carga, vacío, error y reintento. RF30 invalida el prefijo de este reporte al cambiar una incidencia cuando se integren ambos PR.

Sin nuevas migraciones ni dependencias. Se reutiliza la vista de la migración 20261028000004; RF29/#38 sigue siendo dependencia para crear reportes reales. El resumen de alertas RF28 queda fuera de este issue. RF27 también cambia el Panel para añadir su acceso: al integrar los PR se debe conservar ese enlace junto a la gráfica, no elegir una versión descartando la otra.

TypeScript y Expo lint correctos el 22/11/2026. Al retomar la validación pasaron cuatro pruebas de calendario/conteos con `node --test herramientas/pruebas/reporte-mensual.test.cjs`, y la vista se verificó mediante la suite SQL del proyecto en una copia local aislada. Se cubren cambio de año y límite UTC/Lima, meses vacíos, datos inválidos y RLS del agregado. **La revisión visual en el HONOR y la comparación con el servidor compartido siguen pendientes.** No se crearon incidencias remotas para probar ni se acredita todavía aceptación nativa.
